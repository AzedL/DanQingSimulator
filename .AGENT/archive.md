# 归档流程

本流程不默认执行，只在用户明确要求归档时执行。

归档的目标有两个：

1. 为本轮会话生成可检索的 `sessions/*.md`
2. 在人工确认后，最小更新 `summary.md`

## 归档顺序

归档时，按以下顺序进行：

1. 总结本轮会话并生成 `sessions/*.md`
2. 输出对 `summary.md` 的改动建议
3. 等待用户确认
4. 只有在用户确认后，才实际修改 `summary.md`

## `sessions/*.md`

参考 `templates/session-template.md`。

## 对 `summary.md` 的改动建议

在实际修改 `summary.md` 前，agent 应先输出改动建议，并按以下顺序整理：

1. 删除
   - 已错误、过时、被推翻或已无参考价值的内容
2. 修改
   - 仍然有效，但表述、路径、命名或范围需要修正的内容
3. 新增
   - 本轮新确认、且值得进入 `summary.md` 的最小新增内容，包括必要的稳定结论或历史索引入口

输出改动建议时，应优先先删、再改、最后新增，不直接把所有内容都当作新增。

## `summary.md` 的更新原则

更新 `summary.md` 时：

- 基于现有 `summary.md` 与新的 `sessions/*.md` 增量整理
- 不默认重读全量历史 `sessions/*.md`
- 优先保留当前仍然有效、且对后续会话最有价值的信息
- 优先记录架构结论、高风险兼容语义、默认验证方式、关键入口文件与易反复踩坑的问题
- 保持高密度摘要风格，不写成流水账或第二份 README
- 如果某一部分已经变成长篇模块说明，应将细节下沉到对应 `rules/*.md`，`summary.md` 只保留高价值摘要与索引
- 只在当前有效状态发生变化时更新

## 归档时的冲突处理

如果当前代码与 `summary.md` 或 `rules/*.md` 冲突：

- 先标记冲突
- 在归档建议中说明冲突点
- 不直接把未经确认的判断写入 `summary.md`
