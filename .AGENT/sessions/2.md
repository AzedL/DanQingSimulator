# 会话记录 2

## 索引信息

- 主题：把模拟器从旧 `mock` 结构重构为更清晰的分层
- 描述：较早的一轮重构会话，主要确认“旧核心引擎不重写，只收口外围接口、配置和类型”，并删除若干旧兼容出口。

## 会话工作信息

这轮会话的价值主要不在某一个具体 bug，而在于把后续很长一段时间都会用到的结构方向定了下来。

### 这轮先确认了什么方向

本轮主要目标，是继续把模拟器从旧 `mock` 结构重构为更清晰的分层，同时明确：

- 旧核心引擎不重写
- 只收口外围接口、配置和类型
- 新代码优先依赖新的分层入口，不再回流到旧兼容结构

这里最关键的几个设计结论是：

- 旧核心引擎继续保留，后续放在 `src/kernel`
- 旧 `Core / Damage / Fire / Ice / Pulse / Queue` 不改模拟内核逻辑，只是目录从 `src/mock` 改名到新的位置
- `coreOptions.attackPower` 在规则推导中允许被修改，这是有意设计，不作为问题处理
- 默认模拟模式切到 `autoMock`
- 与模拟器相关的默认值集中到配置文件

### 这轮重构后形成的主要结构

这轮会话结束时，项目的主结构已经基本成型为：

- `src/domain`
  - 类型、规则、卡牌元数据、配置
- `src/engine`
  - 模拟入口
  - 自动配卡入口
- `src/features`
  - React 状态编排
- `src/components`
  - 面板与表单组件
- `src/kernel`
  - 旧模拟内核与运行时卡牌实现

从那时起，项目已经不再是“所有逻辑都堆在旧 `mock` 目录里”的状态。

### 这轮同时删除了什么

这轮删除了一批旧兼容层，并明确这些层后续不应恢复：

- `src/mock/index.ts`
- `src/mock/dataBase/dataBase.ts`
- `src/mock/dataBase/lists.ts`
- `src/mock/utils/normalizeMockOptions.ts`

这是这轮重构里很关键的一条边界。  
“保留旧核心引擎”不等于“继续向旧兼容层回流”。

### 默认值和配置在当时的状态

`src/domain/config/simulatorDefaults.ts` 在这轮集中管理了：

- `BASIC_CONFIG_DEFAULTS`
- `DEFAULT_CARD_LOADOUT`
- `SIMULATION_CONFIG_DEFAULTS`
- `APP_VIEW_DEFAULTS`
- `AUTO_SIMULATION_DURATION`
- `AUTO_MOCK_MAX_COMBINATIONS`
- `AUTO_MOCK_TOP_RESULT_COUNT`

当时明确下来的默认行为包括：

- 默认模拟模式：`autoMock`
- 默认结果 tab：`autoMock`
- 自动模拟固定 duration：`600`
- 自动配卡最大组合数：`9999`
- 自动配卡返回 top 数量：`10`

### 关于 AutoMock，这轮留下了什么结论

虽然这一轮不是专门做 `AutoMock` 优化，但当时已经有一些判断：

- `passiveRuntimeDefinitions` 相比“无脑 new Boost”更合理，但不是 auto mock 的主要性能瓶颈
- 性能大头仍然是组合数、每个组合完整执行 `Core.exec()`、以及结果全量排序
- 当时建议后续优先考虑：
  1. 流式 top N
  2. 组合生成与执行流式化
  3. 分阶段筛选或启发式剪枝

需要保留历史语境的一点是：  
在这轮会话发生时，仓库里的 `AutoMock.ts` 仍是“先生成所有组合、再全量模拟、再全量排序”的版本，尚未完成后来的流式 top N 改造。
