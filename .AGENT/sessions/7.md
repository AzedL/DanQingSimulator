# 会话记录 7

## 索引信息

- 主题：`AutoMock` 轻量筛选、命名收口与 Web Worker 异步化
- 描述：本轮围绕自动模拟卡顿问题，先把 `AutoMock` 拆成“轻量 top 筛选 + 完整结果回放”，再把 top 搜索搬进 Web Worker，并在过程中多次收口命名、接口边界与空组合兼容语义。

## 会话工作信息

### 这轮最终落下来的主方案

本轮最终没有走“worker 返回完整 `Core`”或“主线程按当前选中项逐个补图”的方向，而是收口成下面这条分工：

- `src/autoMock/AutoMock.ts`
  - 负责组合计数
  - 负责轻量筛 top
  - 负责按 top 回放完整 `Core`
- `src/engine/autoMock.ts`
  - `runAutoMockGetTop(...)` 返回轻量 top 结果
  - `runAutoMockCoresByTop(...)` 根据 top 结果补完整 `Core[]`
  - `runAutoMock(...)` 返回完整自动模拟结果
- `src/features/autoMock/autoMock.worker.ts`
  - 只做最重的那段：调用 `runAutoMockGetTop(...)`
  - 仅返回轻量 `LightMockResult[]`
- `src/features/autoMock/useAutoMock.ts`
  - 收到 worker 返回的 top 后，在主线程调用 `runAutoMockCoresByTop(...)`
  - 继续对外提供 `autoMockCores`

这样做的意图是：

- 真正拖住页面的是“全量组合搜索 + 轻量模拟”，这部分进 worker
- 主线程只补 top N 的完整模拟，量级很小
- 图表与结果面板继续依赖完整 `Core`，不用把整条 UI 数据流改成 DTO

### 这轮对 `AutoMock` 的关键结构调整

这轮把当前正式 `AutoMock` 收成了下面的职责分离：

- `getTop()`
  - 只负责轻量筛 top
  - 返回 `LightMockResult[]`
- `exec()`
  - 消费 `getTop()` 的结果
  - 回放成完整 `SimulationCore[]`

并且进一步统一了底层执行：

- `mockByCardsCombo(...)`
  - 返回完整 `SimulationCore`
- `lightMockByCardsCombo(...)`
  - 复用同一底层执行，只是启用 `useLightMode`

### 这轮确定下来的命名与边界

本轮有几次命名和边界收口，后续应以最终状态为准：

- `captureTimeline` 改为 `useLightMode`
  - 它表达的是“轻量模拟模式”，不只是“是否采集 timeline”
- `src/autoMock/index.ts` 应直接统一导出：
  - `AutoMock`
  - `mockByCardsCombo`
  - `LightMockResult`
- 不要再额外发明无意义别名：
  - 像 `AutoMockTopItem`
  - 像 `AutoMockWorkerItem = LightMockResult`
  - 像 `mockSimulationCoreByCardsCombo`
  这些都属于噪音抽象，已在本轮收掉

### 这轮修掉的几个关键问题

#### 1. 自动模拟结果 tab 切换时机错误

原先在 `App.tsx` 中，自动模拟点击后立即：

- `autoMock.execAutoMock()`
- `setCurrentTabResult('autoMock')`

但 `execAutoMock()` 已经变成异步 worker 请求，所以真正完成时不一定还会切回自动结果页。

本轮修正为：

- `execAutoMock(onDone?)`
- worker 成功返回后再调用 `onDone`
- `App.tsx` 在完成回调里 `setCurrentTabResult('autoMock')`

同时，`requestId` 被用于丢弃过期 worker 结果，避免旧请求回调覆盖新请求状态。

#### 2. `useAutoMock` 使用了过期 `options` 闭包

本轮中出现过一个很关键的回归：

- worker 返回 top 结果后
- 主线程用闭包里的旧 `options` 去调用 `runAutoMockCoresByTop(...)`
- 导致页面上把默认卡组中的 `林峰` 又带回来了

最终修正方式是：

- 用 `optionsRef.current` 持有最新 `options`
- worker 成功回调中一律使用 `optionsRef.current`

这个坑值得后续优先留意：  
凡是 worker / event handler / timeout 回调里用到可变配置，都要警惕 stale closure。

#### 3. 空组合兼容语义应由 `AutoMock` 自己保证

本轮一度把“空 top 时回退空组合”写到了 `engine/autoMock.ts`，后续又收回到了 `AutoMock` 自己身上。

当前最终语义是：

- `AutoMock` 的 `_comboCount` 至少为 `1`
- `getTop()` 至少返回一个空组合候选
- 空组合轻量候选直接写成：
  - `{ cardsCombo: [], dps: 0 }`
  - 不再白跑一次轻量模拟

这样 `engine/autoMock.ts` 不需要再额外兜底。
